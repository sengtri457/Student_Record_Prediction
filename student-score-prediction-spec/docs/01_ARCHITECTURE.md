# 01. Architecture (End to End)

## Pipeline

```
[1 Collect] -> [2 Validate/Clean] -> [3 EDA + Stats + Plots]
      -> [4 Feature prep + Split] -> [5 Train 2+ models]
      -> [6 Evaluate + Compare] -> [7 Select + Predict + Explain]
      -> [8 Report] -> [9 QA sign off]
```

Each stage reads files from the previous stage and writes files for the next one. No stage depends on another stage's memory. Files are the contract.

## config.yaml (single source of truth)

```yaml
seed: 42
target: final_score
features:
  - attendance_pct
  - study_hours_week
  - assignment_avg
  - midterm_score
  - previous_gpa
split:
  test_size: 0.20
  train_size: 0.80
paths:
  raw: data/raw/students_raw.csv
  interim: data/interim/students_clean.csv
  train: data/processed/train.csv
  test: data/processed/test.csv
  figures: reports/figures
  tables: reports/tables
  models: models
models:
  linear_regression: {}
  random_forest:
    n_estimators: 300
    max_depth: null
    random_state: 42
cv_folds: 5
```

No agent hardcodes a path, seed, or column name. Everything comes from `config.yaml`.

## Component responsibilities

| Module | Responsibility |
|---|---|
| `data_loader.py` | Read raw CSV, return DataFrame |
| `cleaning.py` | Rename, type fix, range checks, duplicates, missing values |
| `eda.py` | Stats table, plots |
| `features.py` | Scaling, split, save train/test |
| `train.py` | Fit models, save `.joblib` |
| `evaluate.py` | MAE, RMSE, R2, CV, comparison table |
| `predict.py` | Predict on test set and on custom students |

## Data leakage rules

- Split first, then fit the scaler on train only.
- If imputing after the split, use train statistics. If imputing before the split, document it.
- Never put `final_score` or anything derived from it in the features.

## Reproducibility

- Fixed seed `42`
- Pinned versions in `requirements.txt`
- Every figure and table is generated by code, not by hand
